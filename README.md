# ☠ NIGHTMARE — штаб клана (ROB RUN)

Сайт клана для отработки тактик по принципу «коллективного разума»: у каждого игрока есть роль, каждый знает свои действия и видит, что в это время делают остальные.

## Что умеет

- **Брифинг**: личная страница игрока с его ролью, обязанностями и задачами во всех тактиках. Есть кнопка «Я понял».
- **Состав**: список игроков. Глава клана выдаёт доступ (логин и пароль), назначает роли и права, может забрать доступ.
- **Роли**: у каждой роли есть название, цвет, значок, описание и список обязанностей.
- **Тактики**: тактика делится на фазы. В каждой фазе есть:
  - схема: фишки игроков, стрелки движения (цвет, пунктир) и подписи на фоне карты;
  - описание фазы и **сигнал перехода** к следующей;
  - действия каждого игрока;
  - таблица **«Кто что делает»**: все игроки × все фазы.
- **Кто изучил**: после каждого изменения тактики видно, кто уже изучил новую версию, а кто нет.
- **Карты**: загрузка скриншотов карт из игры, на них рисуются тактики.

### Права доступа

| Уровень | Что может |
|---|---|
| **Глава** | всё: выдаёт и забирает доступ, назначает роли и права |
| **Офицер** | создаёт и редактирует тактики, роли и карты |
| **Боец** | смотрит всё, отмечает «Я понял», меняет свой ник и пароль |

## Быстрый просмотр (демо-режим)

Пока Firebase не подключён, сайт работает в демо-режиме: все данные хранятся только в твоём браузере.

```bash
python3 -m http.server 8000
# открыть http://localhost:8000
```

## Подключение Firebase (чтобы данные были общими для всего клана)

Бесплатного тарифа Spark хватает с запасом.

1. Зайди на <https://console.firebase.google.com> → **Add project** → любое название (например `nightmare-clan`). Google Analytics можно выключить.
2. **Build → Authentication → Get started → Sign-in method → Email/Password → Enable**. Почта на самом деле не используется: логин `shadow` превращается в `shadow@nightmare-clan.app`.
3. **Build → Firestore Database → Create database** → выбери регион (например `eur3`) → **Start in production mode**.
4. Вкладка **Rules** в Firestore: вставь содержимое файла [`firestore.rules`](firestore.rules) → **Publish**.
5. **Project settings (шестерёнка) → General → Your apps → `</>` (Web)**: зарегистрируй приложение и скопируй объект `firebaseConfig` в [`js/firebase-config.js`](js/firebase-config.js).
6. Если сайт будет на своём домене, добавь его в **Authentication → Settings → Authorized domains** (например `ezdk20000-code.github.io`).
7. Открой сайт: появится экран **«Первый запуск»**, где ты создаёшь аккаунт главы. Этот экран показывается один раз, потом создать главу уже нельзя.
8. Раздел **Состав → «Выдать доступ»**: придумай логин и пароль игроку (пароль можно сгенерировать) и передай их ему лично.

> Ключи из `firebaseConfig` не секретные, их можно хранить в репозитории. Данные защищают правила Firestore: читать и писать могут только участники, которым глава выдал доступ.

## Публикация на GitHub Pages

1. Слей эту ветку в `main` (или выбери её как источник).
2. Репозиторий → **Settings → Pages → Build and deployment → Deploy from a branch** → ветка `main`, папка `/ (root)` → **Save**.
3. Через минуту сайт будет доступен по адресу `https://<user>.github.io/<repo>/`.

## Как забрать доступ и сбросить пароль

- **Забрать доступ**: Состав → ✕ у игрока. Аккаунт перестаёт пускать на сайт.
- **Игрок забыл пароль**: без сервера пароль чужого аккаунта поменять нельзя. Забери доступ и выдай новый под **другим** логином (например `ghost2`). Старый можно удалить в Firebase Console → Authentication.
- Свой пароль каждый меняет сам в **Профиле**.

## Структура

```
index.html               — оболочка страницы
css/style.css            — оформление
js/app.js                — интерфейс: страницы, формы, редактор тактик
js/board.js              — тактическая схема (SVG): фишки, стрелки, подписи
js/store.js              — выбор хранилища (Firebase или демо)
js/backend-firebase.js   — Firebase Auth + Firestore
js/backend-local.js      — демо-хранилище в localStorage
js/firebase-config.js    — конфиг твоего проекта Firebase
firestore.rules          — правила доступа к базе
```
